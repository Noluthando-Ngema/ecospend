Ecospend’s purpose is to help our users track their spending habits and saving goals, but there’s a little more to it than that. Ecospend has taken something as serious and money and managing finances and made it fun. That’s the purpose of Ecospend, it’s to make our users feel more at ease when planning how they’re going to spend their money. That purpose was met when it came to our application and its design, which is related to our next topic. 
Design Considerations
Design considerations are the factors that shape a design which includes requirements and constraints such as branding, standards and user experience (Simplicable.com, 2024). 
Here are Ecospend’s design considerations: 
•	Accessibility- when we talk about accessibility, we talk about designing in such a way that we keep people with disabilities in mind. With Ecospend, we made background of the application as well as what was on it compatible so that users would be able to see the words clearly. 
•	Architecture- means the structure of design and on Ecospend our structure is clear, the application isn’t cluttered, there’s spaces where there needs to be spaces. Not everything is bundled up together especially when it comes to the buttons, they aren’t close together to the point where you press one that wasn’t your intention to press. 
•	Branding- when we’re talking about branding, we refer to things such as identity, image and positioning. When you see the Ecospend logo, you can tell that we’re dealing with money. It’s noticeable from the name, the logo that contains the coin, as well as our landing page where there is a jar with money inside it. Our purpose comes across very easily. 
•	Color- means the use of color techniques such as color harmony and color techniques. With Ecospend our branding is clear, we have primary colors such as green, white and a little bit of brown ever now and again. The logo for the application contains those very colors and when you scroll on each page, those colors exist on every single one of those pages.
•	Engagement- refers to techniques that keep the user engaged and with Ecospend that is the gamification that we have included. So, we included a streaks feature, Ecospend celebrates that you went on the app so, if you go on the app every day, your streak gets higher. We also included a points feature were the user gets 50 points for creating a new envelope category as well as points for staying within their budget, creating a new expense and setting a new goal. 

Utilization of GitHub and GitHub actions 
As we know, GitHub is cloud-based. It’s a cloud-based platform for version control. So, when it came to Ecospend, there were multiple ways we utilized GitHub. Firstly, we pushed our code onto the code repository, multiple times starting from Part 2. Multiple times means we experienced many technical difficulties and had to start over. The code repository is a great place since it’s where all the app’s source code lives, which as stated above and from experience, can live in more than one repository. We also used GitHub’s collaboration feature where team members used the pull requests to review and merge code changes. 
GitHub actions are a built-in CI/CD, which means Continuous Integration Continuous Deployment, automation tool. What it does is run small programs automatically in response to events like pushing code, opening a pull request and creating a release. So, we never really see any of this stuff happening. So, since we pushed the code and opened pull request, here’s how we utilized GitHub actions. So, GitHub has use cases for when certain GitHub actions happen. So, every time we pushed the code, it ran unit/integration test and the use case associated with that or the GitHub action associated with that is “Run tests”. So, when my team members were pulling requests multiple GitHub Actions were taking place such as “Run unit tests”, “Run integration tests”, “Lint the code”, “Type check”, “Security scan”, “Build the app”, “Check for conflicts”, “Deploy preview” and lastly “Check commit format”.
